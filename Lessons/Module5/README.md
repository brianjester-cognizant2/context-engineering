# **Module 5: From RAG to Agents**

This module makes the leap from systems that answer to systems that act. We cover what an agent is (and when you don't need one), how to design tools an agent can actually use correctly, how capability is packaged and shared through MCP and Agent Skills, and the architectures and frameworks that hold it all together.

*   [**Lesson 1: The Rise of AI Agents**](./Lesson1_The_Rise_of_AI_Agents.md)
*   [**Lesson 2: Designing and Integrating Tools**](./Lesson2_Designing_and_Integrating_Tools.md)
*   [**Lesson 3: Agentic Frameworks and Architectures**](./Lesson3_Agentic_Frameworks_and_Architectures.md)
*   [**Lesson 4: MCP and Agent Skills — Packaging Capability**](./Lesson4_MCP_and_Agent_Skills.md)

---

### **By the end of this module you will be able to:**

1. Decide whether a problem needs an agent, a workflow, or neither
2. Write tool schemas, error contracts, and result shapes an agent can use correctly
3. Choose an agent architecture and insulate yourself from the framework
4. Package capability as tools, MCP servers, skills, or project instructions

**Estimated time:** 4-5 hours, including the hands-on tasks.
